Prompt Injection

planned by Fable 5 · built by Opus 5 click the game, then type

Two models, one pipeline

Hostile prompts descend toward your context window and you are the alignment layer. Type a word to lock on, finish it to destroy it. Every fifth wave a full injection attack arrives as a phrase you dismantle word by word.

The interesting part isn't the game — it's how it was made. One model wrote the design document. A different model implemented it. No human wrote any code or any asset.

The plan

Claude Fable 5 wrote a full design document — enemy speeds, difficulty formulas, scoring, and a motion-design section specifying every animation — before any code existed. It was never revised to match the result.

The build

Claude Opus 5 fixed an interface contract first, then had nine agents write nine modules in parallel against it. Integration, four independent verifier agents, then fix rounds.

The proof

An acceptance gate drives the finished game in a real browser: 21 checks covering scoring, the boss fight, death and restart, frame rate under load, and zero runtime errors.

Canvas 2D Zero dependencies Zero network requests 5,555 lines One file WebAudio — no sound files

Everything you hear is synthesised at runtime and everything you see is drawn procedurally — there isn't a single image or audio file in the project. Profiling cut the background from 4,361 draw calls per frame to 316.
